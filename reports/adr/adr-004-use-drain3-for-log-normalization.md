# ADR-004: Использование Drain3 для нормализации логов

**Дата:** 2025-11-10  
**Статус:** Принято  
**Контекст:**  
Логи Azure DevOps содержат тысячи почти идентичных строк, отличающихся лишь динамическими значениями (ID сборок, пути, временные метки), которые мешают обучению моделей на тексте. Например:
```
2020-11-12T06:14:33.7222246Z TimeoutInMinutes: 180
2020-11-12T06:14:33.7222246Z Got build number: 0.0.1.0
```
Эти значения создают "шум", делая модель неустойчивой и требующей огромного объема данных.
Прямая работа с «сырыми» строками делает обучение моделей дорогим и нестабильным:  
- высокая размерность входных данных;  
- переобучение на конкретных значениях;  
- невозможность инкрементального обновления шаблонов.


**Решение:**  
Использовать библиотеку **Drain3** — реализацию алгоритма кластеризации логов через построение дерева шаблонов.  
Drain3:
- извлекает уникальные шаблоны (`<TFS_Section> <*>`);  
- присваивает каждому шаблону постоянный `event_id` (E1, E2 …);  
- поддерживает инкрементальное обновление состояния (`drain_state.json`).
- заменяя динамические части на `<*>`.  
Пример:
- Вход: `"TimeoutInMinutes: 180"` → Выход: `"TimeoutInMinutes: <*>"` → `event_id: "E3"`
- Результат: миллионы строк → ~5000 уникальных `event_id`

**Последствия:**  
✅ **Плюсы:**  
- Устойчивость к изменениям формата логов  
- Сжатие данных: 100K+ строк → 5K шаблонов  
- Возможность использования `event_id` как категориальных признаков  
- Поддержка инкрементального обучения через `drain_state.json`
- Возможность дообучения на новых логах без полного пересчёта.  
- Унификация представления между train и inference.

⚠️ **Минусы:**  
- Требуется сохранение и версионирование `drain_state.json` для воспроизводимости  
- Нет поддержки новых шаблонов без перезапуска кластеризации
- Чувствительность к параметрам `sim_threshold` и `max_children`; требует настройки.  
- Плохо справляется с highly-dynamic структурами (JSON, XML).  
- Любое изменение правил нормализации требует перезапуска всего пайплайна.

**Связанные файлы:**  
- `drain_templates.json`  
- `drain_state.json`  
- `drain_sequences.jsonl`  
- `drain_mapping.jsonl`

**Решение принято:** AB, 2025-11-10
