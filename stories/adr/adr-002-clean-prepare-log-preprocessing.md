# ADR-002: Предобработка логов — Clean → Prepare

**Дата:** 2025-11-10  
**Статус:** Принято  
**Контекст:**  
Сырые логи Azure DevOps содержат технический шум:
- Временные метки (`2020-11-12T...Z`)
- Декораторы (`##[section]`, `##[error]`)
- Разделители (`********************************************************************************`)
- Пустые строки, отступы

Это мешает Drain3 и снижает качество кластеризации.

**Решение:**  
Ввести два этапа предобработки:
1. **Clean**:  
   - Удалить временные метки, `##[section]Finishing`, `##[debug]`, разделители  
   - Удалить пустые строки и лишние отступы  
   - Сохранить только строки с `##[section]Starting` и `##[error]`

2. **Prepare**:  
   - Преобразовать `##[section]Starting: ...` → `<TFS_Section> ...`  
   - Преобразовать `##[error] ...` → `<TFS_Error> ...`  
   - Нормализовать динамические значения: `180` → `<*>`, `0.0.1.0` → `<*>`

**Последствия:**  
✅ **Плюсы:**  
- Повышение качества кластеризации Drain3  
- Унификация формата логов  
- Поддержка тегов (`<TFS_Section>`, `<TFS_Error>`, `<TFS_Task>`)  
- Устойчивость к изменениям формата логов

⚠️ **Минусы:**  
- Требуется поддержка регулярных выражений  
- Возможны ошибки при обработке нестандартных логов

**Связанные файлы:**  
- `clean.py`  
- `prepare.py`  
- `cleaned_logs/`

**Решение принято:** AB, 2025-11-10
