# ADR-011: Восстановление логов с подсветкой аномалий

**Дата:** 2025-11-10  
**Статус:** Принято  
**Контекст:**  
Инженеры не работают с `event_id=E99`. Им нужны **читаемые логи** с указанием, где произошла аномалия. После обнаружения аномалии нужно показать инженеру **где именно** в исходном логе проблема.

**Решение:**  
После обнаружения аномалии в `anomalies.jsonl`:
1. Взять `event_id` из `drain_sequences.jsonl`
2. Найти соответствующий `template` в `drain_templates.json`
3. Найти `original_line` в `drain_mapping.jsonl`
4. Заменить динамические значения на `<*>`
5. Пометить аномальные строки как `[ANOMALY]`

Пример вывода:
```
<TFS_Section> Prepare job Job_1
ContinueOnError: False
TimeoutInMinutes: <*>
[TFS_Error] The process cannot access the file...
[ANOMALY] <TFS_Task> Unexpected task execution: CleanupTempFiles
```

**Последствия:**  
✅ **Плюсы:**  
- Возможность восстановить исходную строку через `drain_mapping.jsonl`.  
- Удобство отладки и визуализации.
- Интерпретируемость результатов  
- Возможность автоматической генерации отчетов  
- Сохранение структуры оригинального лога

⚠️ **Минусы:**  
- Требуется доступ к `drain_mapping.jsonl` и `drain_templates.json`  
- Не поддерживает логи без шаблонов
- Дополнительный объём диска (~50 MB на 1 M окон).  
- Необходимо поддерживать синхронность `meta` и `sequences` при дообучении.


**Связанные файлы:**  
- `reconstruct_logs.py`  
- `anomalies.jsonl`  
- `reconstructed_logs/`

**Решение принято:** AB, 2025-11-10
